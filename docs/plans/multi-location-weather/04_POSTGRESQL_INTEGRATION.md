## 4. Isolation, idempotency and operational limits
Proposed initial weather-app DB pool: `pool_size <= 2`, `max_overflow=0`, 5–10 second statement timeout for ordinary ingestion/read queries, 2s connect timeout, bounded batch size <=100 events or <=500 observation rows, one producer instance; these are **proposed budgets** and MUST be revised against measured PG `max_connections`, observed my-pa resource usage and test benchmarks. Use INSERT ... ON CONFLICT for event identity and sample idempotency; **never** use blind REPLACE/DELETE. Source event and dependent observations enter same transaction. Provider pagination/watermarks advance in same or safely replayable unit of work. If DB responds overloaded/timeout, back off with jitter, keep bounded receiver spool and reflect stale state; never spin retry loops.

Indexes: unique raw `(source_id,provider_event_key,revision)` or receiver UUID; `observations(assignment_id,metric_code,observed_at DESC)`; `model_values(assignment_id,valid_start DESC,metric_code)`; `raw_events(received_at)`; `source_assignments(source_id,effective_from)`; `poll_state(next_permitted_at)`. Test actual queries with `EXPLAIN (ANALYZE, BUFFERS)` in scratch populated with synthetic time-series. Partition monthly only if measured retention/delete performance justifies it; partition design and unique keys are interdependent and must be re-reviewed before any migration claiming global uniqueness.

**Volume planning example (not an observed workload):** 1 WH65B packet every ~16s yields about 5,400 packets/day. At 8 metrics each, unthrottled normalized storage can approach ~43,200 metric rows/day (~15.8M/year) *before* remote locations. PostgreSQL indexes/WAL substantially increase on-disk bytes; measure with synthetic inserts, not a fixed GB promise. **FK-compatible example, not approved retention:** keep immutable `raw_events` identity/digest at least as long as referenced observation/model records (e.g. >=24 months); only separately stored `raw_event_payloads` may qualify for optional 90-day payload expiry under future operator authorization. Fine-grain observations may be retained 12–24 months and derived caches longer if approved; **no automated purge** without separately operator-approved retention schedule and a tested weather-only backup/restore/delete workflow.

### 7.3 Provenance-preserving illustrative retention

A **90-day payload / 24-month observation** example is feasible because immutable `raw_events` metadata remains for >=24 months, and only optional `raw_event_payloads` bytes can be removed *after* an independently authorized operator retention action. Historical joins preserve event ID, SHA-256 digest, decoder version, source, device, measurement and ingestion times; deleted payload means original bytes can no longer be re-normalized, so do not claim byte-perfect replay after expiry. The physical event metadata and all referenced observations stay nondeletable under normal grants. Before any future retention action, require licensing/privacy classification, full consistent my-pa backup, scratch-only authorized payload-expiry simulation, FK verification and before/after restore/digest evidence. **No purge, grants, credentials, DDL or live SQL are permitted under this plan.**

## 8. CR-3 NF-001 — mandatory database-enforced geographic owner equality (PROPOSED, NOT EXECUTED)

**Review source:** `LHW-CR2-INDEPENDENT-PLAN-REVIEW-20261023-001`, reviewed previous HEAD `d0739f9e4ceba5ee45e8ba8ab8891cb68c994e23`, tree `45d2ead414320e275cb97d31f819f7a944f55e47`, disposition `PLAN_REVISION_REQUIRED`. This section selects **database-level composite FKs**, not API-only validation or an unspecified trigger.

**Normative proposed schema constraints (illustrative SQL contract, not a migration):**

```sql
-- Product classification is immutable and DB-owned, not supplied by ingestion JSON.
CHECK ( (stream_class = 'FORECAST_MODEL' AND assignment_id IS NOT NULL)
     OR (stream_class = 'MEASURED_STATION' AND assignment_id IS NULL) ); -- provider_streams
UNIQUE (stream_id, source_id, assignment_id, stream_class); -- provider_streams
-- Forecast/model parent: all four columns NOT NULL; stored stream_class
-- restricted by CHECK (stream_class = 'FORECAST_MODEL').
FOREIGN KEY (stream_id,source_id,assignment_id,stream_class)
  REFERENCES weather.provider_streams(stream_id,source_id,assignment_id,stream_class)
  ON UPDATE RESTRICT ON DELETE RESTRICT; -- model_runs
UNIQUE (model_run_id,stream_id,source_id,assignment_id,stream_class); -- model_runs
-- Model value: identical four NOT NULL keys and fixed FORECAST_MODEL class.
FOREIGN KEY (model_run_id,stream_id,source_id,assignment_id,stream_class)
  REFERENCES weather.model_runs(model_run_id,stream_id,source_id,assignment_id,stream_class)
  ON UPDATE RESTRICT ON DELETE RESTRICT; -- model_values
FOREIGN KEY (stream_id,source_id,assignment_id,stream_class)
  REFERENCES weather.provider_streams(stream_id,source_id,assignment_id,stream_class)
  ON UPDATE RESTRICT ON DELETE RESTRICT; -- model_values
-- Keep (model_values.assignment_id,source_id) → source_assignments and
-- (model_runs.event_id,source_id,stream_id) → immutable raw_events.
```

These are proposed clauses to be placed on their stated owning tables by a **future my-pa-owned, independently authorized Alembic migration**, not one executable multi-table SQL statement. SQL parent composite UNIQUE index and compatible column types are mandatory. `model_runs` and `model_values` have `assignment_id`, `source_id`, `stream_id` and class **NOT NULL**; PostgreSQL `MATCH SIMPLE` must not be used with a nullable modeled component to bypass an FK. The measured-station `provider_streams.assignment_id IS NULL` exception applies solely to source-qualified remote **measured** `observations` and cannot be referenced by model tables; no model value may use the measured-stream class. The signed provider product class/site/source/owner fields cannot be rewritten via UPDATE, direct app DML or metadata-admin retirement; a change to geography, model, relative horizon or owner assignment creates a **new** stream and audit transition.

Resolve and register a coordinate-specific stream's assignment as of its **provider retrieval or actual proven issue event** (record whichever temporal basis is available); retain the original immutable link for all future validity intervals, even if assignment later retires. Parent registered source and assignment are locked under the common source→station→device→assignment→raw_event discipline for admission/retirement. The future my-pa DB owner must prove each lock path and concurrent retire-versus-model-insert using disposable PG, not merely application prechecks.

**Same-source A/B counterexample to deny:** source S has two simultaneously valid `source_assignments` a→location A and b→B. `provider_streams(sA,S,a,FORECAST_MODEL)` yields run rA; `provider_streams(sB,S,b,FORECAST_MODEL)` yields rB. Correct values rA/sA/a and rB/sB/b commit. An insertion `model_values(rA,sA,S,b,FORECAST_MODEL)` **fails the composite FK** even though `(b,S)` is a legitimate source assignment; model run rA cannot itself be created with assignment b. An identical NWS upstream **MEASURED_STATION** stream has NULL owner assignment and legitimately produces two distinct `MEASURED_REMOTE` observation rows for a and b, never model values. Prove rollback/no row/cursor change; negative tests AT-011/013/016/021, SC-02/05 and I-01/06/11/12.
