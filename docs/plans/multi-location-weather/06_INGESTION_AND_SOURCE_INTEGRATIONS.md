RF troubleshooting order: host cannot enumerate -> physical USB/DSM issue; host enumerates but container blocked -> passthrough/kernel driver/permissions; receiver opens but zero valid packets -> try antenna placement, gain/frequency correction and CRC; wrong models -> inspect decoder version, test protected IQ capture only if evidence permits, never publish raw RF unnecessarily; DSM cannot grant stable USB -> use the **same dongle on a small compatible Linux host** as conditional fallback, with authenticated private relay to NAS, no new station and no default purchase. One SDR may decode multiple co-located sensor types; 915 MHz alone is not a multi-location source strategy. ## 2. Local receive envelope and decoder mapping
Sender obtains `receive_utc` from reliable monotonic/system clock correlation, `receiver_event_id` UUID generated at first physical reception, stable for retransmission; `boot_id`, `sequence`, exact decoder build SHA, RF model/ID, captured JSON and SHA-256 canonical-byte digest. Serial selection only after observing actual EEPROM serial; the scaffold sample `00000001` is not a true identity. Large/noisy/unknown devices are quarantined with counts, not added automatically. Expose a registered local decoder mapping table keyed by decoder version/model and observed field names.

| rtl_433 candidate output | Canonical metric / handling |
|---|---|
| `temperature_C`, `humidity` | `air_temperature` degC, `relative_humidity` percent; indoor WH32B maps to distinct indoor metrics |
| `wind_avg_m_s`, `wind_max_m_s`, `wind_dir_deg` | `wind_speed`, `wind_gust`, `wind_direction`; preserve sensor averaging/instant scope |
| `rain_mm` | **cumulative counter** `rain_counter` mm; derive period rain separately with epoch-aware continuity |
| `uvi` | `uv_index`; absent != 0 |
| `light_lux` | `illuminance` lux; do not infer W/m2 from lux |
| `pressure_hPa` | `barometric_pressure` only if valid conditional decoder field genuinely observed and sensor/module provenance established |
| `battery_ok` | Device health/quality metadata; never a weather field and model semantics must be confirmed |
| `mic`, decoder annotations, `id`, `model` | Verification and provenance only; invalid checksum, unknown IDs or malformed fields quarantined |
Map field keys and parser revisions with real captures before implementation accepts real live samples. Unknown extra fields can be retained in sanitized raw event, not automatically added to domain metrics. Measurement event timestamps from local collector are **receive-time estimates** absent authenticated sensor clock. Clock skew detection and time synchronization acceptance required.

## 3. Bounded receiver-forwarding contract
- Receiver uses pinned rtl_433 (either own build from version-pinned source or immutable audited image) and a small line reader inside same container. Persist ingress envelope **before** HTTP send to a NAS-local restricted spool (`0600`, bounded by size/age). Cache flush/fdatasync semantics and error recovery are test targets; environment lacks evidence of supported NAS storage path.
- Send batches in stable reception order to `POST /internal/rf-events`; authenticated header/HMAC and route isolation, do not log secret. Stable event IDs survive retries, preserved input payload bytes allow digest verification.
- API commits raw event and accepted metrics atomically, and acknowledges exact list of event IDs/digests only after commit. Receiver deletes/ack-marks spool entry only after reply covers it. 409 digest mismatch halts that ID; 422 schema fail quarantines, alerts; 503/timeout invokes exponential retry and remains staged. This prevents silent loss due to transient app/DB unavailability but **cannot reconstruct broadcasts missed when SDR was off**.
- Spool saturation: refuse silent rotation/drop and raise critical storage alert; operator policy may allow oldest drop only with acknowledged loss budget and permanent gap evidence. Unregistered device packets handled as sanitized aggregate counters; avoid durable storage of private neighboring RF traffic.
- No MQTT needed; only one local producer and one app consumer. If a need for fan-out appears, ADR for authenticated broker rather than enabling existing `allow_anonymous true` config.

## 5. Provider adapter exact contracts
**Registration:** operator registers `source_id`, provider code, terms/attribution reference and checked date, selected location assignment, provider-station/site identity and coordinates if required, product kind, metric allowlist, expected cadence, allowed retention and max requests/day, credential *reference* only. No credentials in public repo. Refuse polling if source not approved/active; show stale/unavailable rather than fabricating default provider values.

**NWS:**
- Discover `/points/{lat},{lon}` and links to `forecast`/`forecastHourly`; discover station list for the returned grid and register an appropriate station ID based on geographic distance/quality. Do not automatically assert station represents local coordinates.
- HTTP `User-Agent` identifiable application (contact address optional and stored privately, never invented), `Accept` expected type, TLS verification, ETag/Cache-Control. On 429/503 retry after `Retry-After` if provided and bounded backoff; NWS published rate limit not a stable numeric constant.
- Parse quantity `{value,unitCode,qualityControl}`, observations `timestamp`, forecast periods `startTime/endTime`, precise site. Null measurements remain unavailable. Pressure may mean sea-level vs station; preserve variable semantics. Reject invalid unit codes rather than assume degC/hPa. API may return malformed/missing fields -> quarantine and health event.
- Limit history bootstrap to actually provided observation window (~7d); do not backfill months of made-up historical readings. Stored weather history begins when authorized collection operates.

**Open-Meteo:**
- Explicit latitude/longitude and requested variables, unit choices fixed to documented SI equivalents, `timezone=UTC` for machine timestamps. Preserve `elevation`, `generationtime_ms` and model code when available; distinguish data source model output vs observation.
- **Forecast run identity hazard:** Open-Meteo's automatic Best Match response is a stitched current model product, not necessarily a unique atomic model run. If no reliable run ID returned, derive `retrieval_snapshot_id` and `model_run_identity_status=UNKNOWN`, and prohibit claiming individual-run provenance. For actual run-specific forecast comparisons consider separate Single Runs API only if entitlements permit. Keep each changed response as new provider snapshot revision with source digest.
- Limit calls to registered sources / thresholds strictly below free terms, with weekly audit of usage; display required attribution with link and modification note; stop/free path when usage becomes commercial or terms otherwise change.

**Polling correctness:** `poll_state` cursor updates in same transactional unit as successful persistence (or replay-safe deterministic handoff). 304 -> record unchanged fetch heartbeat; 429 -> no cursor advance, respect Retry-After; 401/403 -> stop and alert; 5xx/timeouts -> bounded exponential retry; permanent schema drift -> quarantine sample and stop source until reviewed; network offline -> last success remains but freshness declines. Omit provider requests from CI; use recorded **synthetic/redacted** fixtures not unredacted personal location. Rates depend on real provider headers, not invented.

## 6. Normalization and quality pipeline
Input order: validate transport envelope+size/version -> authenticate source/device and assignment at event time -> validate decoder model, checksum indicator and payload types -> source-specific field mapping -> canonical unit conversion -> physical plausibility and sensor-specific bounds -> dedup/correction determination -> **one DB transaction** -> ACK. Invalid records get stable rejection/quarantine diagnostic and no accepted observation (authorization to retain quarantined raw data is separate). Record `REJECTED`, `SUSPECT`, `ACCEPTED` and reason (machine-safe, not sensitive values). Never turn absent values into zero or fill pressure from unproven station field. Metric update precision and range versions must be pinned; rain continuity and local-day calculations require the state machine in [05](05_WEATHER_DATA_MODEL.md).

Corrections create new observation linked by `supersedes`, not UPDATE of accepted rows. Cross-source differences are not a reason to deduplicate. Provider revision identity and forecast issuance/cycle are independent dimensions. Receiver 16s observations may be aggregated for hourly/daily chart queries only with completeness and correct time boundaries; default never silently downsample raw events as authority.
