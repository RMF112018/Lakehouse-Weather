# 05 — Multi-location, source-aware weather data model
**Package LHW-ML-20261023 | CP-3 | STATUS: PROPOSED | Not production DDL.**
Design goal: multiple independently configured geographic locations; **only the local WS-2000 installation communicates with the NAS SDR**; external locations use authorized network providers. Must preserve sensor and upstream origins across hardware changes, outages, corrections and conflicting sources.

## 1. Identity and cardinalities
- **Location** is a named geographic destination/site with time zone, optional coordinates/elevation and privacy class; never a sensor ID or weather API key. Stable UUID across relabeling. Coordinates required when calling lat/lon provider; otherwise mark location unresolved until supplied by operator.
- **StationInstallation** groups local hardware (WH65B outdoor plus optional WH32B indoor/pressure) and survives sensor replacement or movement. Not itself a geographic coordinate.
- **Source** is a stable logical origin (`ambient_local_station`, `nws_observation_station:{site-id}`, `nws_grid_forecast:{grid-id}`, `open_meteo_model:{model/config}`). A source may serve multiple locations, but **`provider_stream_id` is the independently polled product identity**: a measured NWS station stream may be shared across assignments; each coordinate/assignment-specific NWS forecast or Open-Meteo model request has its own immutable stream and cursor. A local ambient source may map to only one geographic site at an instant.
- **Device** is a *physical sensor identity epoch* within a station. WH65B and WH32B have different devices, models, RF IDs, optional low-battery and capabilities. A replaced sensor or previously reidentified device gets a **new epoch/UUID** until physically attested otherwise; historical old device stays unchanged. RF ID by itself is **not globally unique**.
- **SourceAssignment** links a source and a location with `effective_from <= observed_at < effective_to` (or open interval), preserves provider observation-site geometry separately from selected location geometry and preference rank. Retire/append epochs, no silent change to history; reject conflicting active local installation assignments and unauthorized many-to-many duplicates. Source preferred rank is a **view selection policy**, never a fact overwriting records.
- **RawEvent** is immutable long-lived event **metadata**, containing exact event/source ID, physical device ID for local RF, qualified provider `stream_id` for modeled retrieval, receive/fetch/ingest times, original response SHA-256 and decoder/provider version. Source/stream composite FKs bind any model snapshot to this event. Sanitized original JSON bytes reside separately in optional `raw_event_payloads`; future operator-gated byte expiry must not sever observation/model lineage or destroy the referenced event/digest.
- **Observation** is only a measured environmental condition: one metric, one canonical numeric value/unit, UTC `observed_at`, `observed_at_basis` (`sensor_clock/provider_timestamp/receiver_clock`), `ingested_at`, source, assignment, optional device, raw event, validation outcome, normalization version. No forecast is an observation.
- **ModelRun/ModelValue** stores forecasts, nowcasts and modeled analyses separately. For `stream_class=FORECAST_MODEL`, **both run and value carry required NOT NULL `stream_id,source_id,assignment_id`** and DB composite FKs to the **same immutable provider stream owner**; each value additionally matches its exact run including assignment and class. Parent stream's source/assignment/site and owner cannot be changed or re-bound. Real issued time may be NULL when unknown. The measured station stream (`MEASURED_STATION`, null owner assignment) is a separate physical observation path and cannot create model runs/values. Must never be presented as measured.
- **ProviderStream** identifies an immutable *product* using admitted provider+entitlement and immutable stream class: `FORECAST_MODEL` has **non-null assigned destination** with `(source_id,assignment_id)` FK and location/coordinate/product identity; `MEASURED_STATION` has **null assignment** and is permitted only for genuinely identical upstream measured-station observations. `FORECAST_MODEL` cannot use this nullable station exception. Every modeled run/value must satisfy composite stream/source/**assignment**/class FKs at PostgreSQL level, not separate source-only FKs or caller validation. Relative horizon, variable/unit/model/site selection remain versioned stream identity. Rolling poll-specific absolute start/end are request evidence, never part of stream key. `PollState` tracks independent `stream_id` cursors/backoff/freshness; quota is provider-entitlement-wide. Changed site/product policy requires an audited new stream. Operational freshness never substitutes for meteorological quality.
- **Aggregate (conditional)** is an optional **rebuildable derived cache**, after a performance benchmark and separate contract review, with cutoff, complete input/source lineage and algorithm version. MVP derived rainfall needs **no persisted interval table** and is not a measured observation.

## 2. Canonical metric registry and units
MVP closed registry (expand only under reviewed versioned mapping):
| code | canonical unit | eligible data sources | policy |
|---|---|---|---|
| `air_temperature` | `degC` | WH65B outdoor; WH32B indoor distinguished as `indoor_air_temperature`; provider measured | no indoor/outdoor merging |
| `relative_humidity` | `percent` | WH65B outdoor; distinct `indoor_relative_humidity` | validate 0–100 |
| `wind_speed` / `wind_gust` | `m/s` | WH65B or qualified provider | gust semantics source-dependent, preserve interval definition |
| `wind_direction` | `degree` | WH65B or provider | normalize [0,360), circular aggregation; calm => null if direction undefined |
| `rain_counter` | `mm` | WH65B cumulative counter | never display as rain rate or local-day rainfall total |
| `rain_increment` / `rain_rate` | `mm` / `mm/h` | **DERIVED-ON-READ** from pairs of physical counter observations; never stored as `MEASURED` | reset/rollover/gaps invalidate deltas; expose predecessor/current observation UUIDs, computation version, as-of and quality |
| `barometric_pressure` | `hPa` | independently verified `Fineoffset-WH32B` packet, separately identified `Fineoffset-WS69`/other real qualified model, or measured remote site | neither inspected `Fineoffset-WH65B` decoder branch populates pressure; the cited optional branch belongs to `MODEL_WS69` only. Preserve pressure basis/site |
| `uv_index` | `index` | WH65B when emitted | not zero when unsupported |
| `illuminance` / `solar_irradiance` | `lux` / `W/m2` | WH65B when emitted | cannot arbitrarily convert lux to W/m² |
Additional models (dew point, feels-like, pressure trend, daily rain, highs/lows, sunrise) are derived views with recorded algorithm/version; do not claim independently sensed. Unit conversion occurs once on ingest with versioned rule. Storage numeric precision: preserve decoder supplied significant digits; no fabricated significant figures.

## 3. Ingestion identity and idempotency
**RF:** `rtl_433` output lacks trustworthy sensor clock or globally unique sequence number. Capture an immutable `receiver_event_id` (UUID) **before** forward/retry; attach monotonically tracked receiver boot ID, receive UTC, decoder code/version and RF ID; persist envelope for bounded replay. `UNIQUE(source_id,receiver_event_id)` assures idempotent retries. Identical payload bytes in different genuine 16s broadcasts are distinct observations. Optional near-duplicate suppression must be evidence-tested and never use `hash(payload)` alone. Sensor clock cannot be invented: `observed_at=receiver UTC` with `observed_at_basis=receiver_clock`.
**External observation API:** use stable provider observation ID/site + measured timestamp + metric where provider supplies it. Store `provider_event_key` and payload hash; repeated identical requests are idempotent. **Provider correction** with same key but changed value creates a new revision/event and appended `supersedes_observation_id` link; never delete the earlier reading. If provider does not guarantee stable IDs, define tested derived key with its limitation recorded.
**Forecast/model:** distinct immutable product `stream_id` persists across rolling request windows. Model retrievals carry source/stream-checked immutable raw event ID/full response digest, a separate **versioned semantic product digest** over normalized values/validity/source/model/units and real issue data when known, and a retrieval snapshot revision. For a real provider run with verified issue identity, enforce that identity and snapshot-to-immutable **origin assignment at actual proven issue or retrieval time**; for stitched Open-Meteo Best Match, set `run_identity_status=UNKNOWN`, `issued_at=null` and use `(stream_id,semantic_digest,retrieval_revision)` with stable dedupe/append-only supersession instead of fabricating `run_timestamp/issue_timestamp`. Same semantic content with altered fetch/response generation timing is heartbeat only. A new true forecast issue or changed semantic content appends a distinct immutable revision; never overwrite physical observations.
**Replay:** each event has parse version, source contract version, validation results; replay same version produces same normalized values. A new normalizer version may produce linked corrections, not change existing row bytes. Record permanent rejection/quarantine reason for unregistered IDs and invalid measurements without inventing a location.

## 4. Temporal authority and source movement
All instants stored as `timestamptz` in UTC. User location has **IANA zone** to derive local display date and calendar-bound buckets, including DST 23/25-hour days. For WH65B, receive timestamp marks approximate packet measurement time and separate ingestion timestamp marks DB commit; if receiver clock skew exceeds proposed 30s, reject or quarantine. Provider timestamps with timezone offsets are parsed strictly, never attached to operator local timezone by default. NWS station issue time, receive time and forecast model issue/validity time are different concepts.

Assignment uses half-open effective ranges to preserve a device/station relocation. Do not rewrite past observations on reassignment. If a source moves to a new location, append a new assignment and retire old one. Changing a user-friendly location name keeps `location_id` stable. When station RF ID changes, stop matching old ID and open a new device epoch after physical evidence; station `source_id` remains stable. Conflicting RF broadcasts from unknown IDs are quarantined, not joined by guessed identity.

## 5. Rainfall algorithm (D-007)
Raw `rain_counter` is a cumulative gauge amount; meaning/reset range must be established on physical decoder test before converting into true accumulation.
1. Sort accepted consecutive samples by `observed_at,event_id` *within same physical rain sensor identity epoch*.
2. A prior valid value is required. First sample after startup/replacement: `rain_increment=NULL`, continuity `initial`; cannot backfill unknown history.
3. If `current>=previous` and elapsed/physically plausible, `delta=current-previous`; **return** derived zero if exactly equal, with an on-read result carrying predecessor/current measured observation IDs and algorithm version; do not insert a measured observation.
4. If `current<previous`, set `rain_increment=NULL` and continuity `counter_reset_or_rollover_unknown`. **Do not add an assumed modulus** until device-specific modulus is verified; if verified, version a precise rollover rule.
5. For missing packets/long gaps, conflicting RF IDs, parser error, duplicate correction, implausible jump or clock skew, mark interval `partial/unknown`; do not pretend a zero-rain interval.
6. For a local calendar day, bucket increments by event/interval and IANA local-day convention. An interval crossing local midnight without subinterval evidence must be flagged `boundary_uncertain` rather than perfectly apportioned.
7. Rain rate `mm/h` requires a defined averaging window with elapsed seconds and enough valid samples. Never equate accumulated rainfall with rain rate. Daily aggregate includes `completeness_ratio`/quality state; UI flags partial days and reset.
8. Station/device changes create a continuity break unless an independently verified counter transfer is possible; resetting on hardware replacement does not erase historical records.

Wind/gust: gust maxima are interval-specific, not comparable across feeds without interval metadata; wind direction circular mean weighted by speed when meaningful; reject north/east arithmetic wrap-around errors. Pressure unit and station/sea-level definition must be preserved; do not silently compare adjusted sea-level pressure to raw station pressure.

## 6. Preferred-source / conflicts and freshness
Each location displays an explicit **source badge on every metric or grouped panel**. Metric-specific priorities select among sources, not one global source. Selection conditions: measurement class, explicitly assigned site, quality accepted, freshness within per-source TTL, metric capability, operator preference, then deterministic tie-break by `source_id`. Do not automatically promote NWS observation to "local station", model estimate to observation, or stale value to current. Conflicting valid sources remain separately queryable with their own timestamp/site; display "sources disagree" if outside metric-specific tolerance (tolerance itself proposal), not an averaged fabricated observation.
Example **proposed** staleness warnings: WH65B no accepted packet for >2min; NWS observations >30min or provider-declared update cadence; Open-Meteo forecast beyond last declared model validity; final thresholds depend on verified cadence. Distinguish provider outage, unknown source, rejected metrics, missing sensor and stale accepted last reading. A disconnected *already-open tab* may show its prior **in-memory** values labeled OFFLINE/as-of; a fresh offline load may cache only static assets and must show weather unavailable, not a durable saved weather view.

## 8. Data protection and retention
No user addresses, precise coordinates, RF recordings, API keys or private home-site information in public repository fixtures/logs. Use synthetic UUIDs and neutral labels. Real site geometry resides only in approved weather tables; no public telemetry. Sanitize/size-bound provider responses; role-limited reader cannot access `knowledge` or other my-pa personal data. **Immutable raw event metadata and SHA-256 must outlive every referencing observation or model snapshot** (e.g., 24 months when such rows are retained). Only optional `raw_event_payloads` bytes may have an **illustrative, future operator-approved 30–90-day** expiry; this is neither approved retention nor deletion authority. Derived caches may be kept longer only after approved budget. Models remain FK-bound to raw event metadata after payload-byte expiry, so byte-perfect replay may cease but provenance joins survive. Every API response must carry appropriate source/time provenance; `issued_at` is NULL if a true provider run issue time is unknown.

## 9. Formal executable invariants
I-01: no observation without valid event, source, assignment, matching time range and finite canonical value.
I-02: every physical local sensor observation requires nonnull device identity equal to the device of its referenced immutable raw event (including two different devices on the same station), checked in the database; provider-null device semantics are separately checked, never bypassed by a nullable composite FK.
I-03: provider measured, model analysis and forecast are visibly distinct all the way to UI.
I-04: replay of identical first-seen receiver_event_id or provider event revision is content-idempotent/row-count-invariant; model Best Match semantic product equality is versioned and not keyed to an invented run timestamp.
I-05: corrected values append supersession lineage; never mutate historical evidence.
I-06: no cross-location reassignment of past observations **or modeled values** after assignment retirement; the coordinate stream's origin assignment is immutable and DB-enforced.
I-07: a blank/missing/invalid sensor metric is null/not served, never zero or invented estimate.
I-08: loss/outage/restart never silently advances collection watermark past uncommitted records.
I-09: rain reset/unknown boundary marks incomplete, never negative or fabricated gain.
I-10: database schema owner and app role have disjoint migration/data privileges, and weather app has zero access to my-pa private schemas.
I-11: model values cannot appear in observation-only endpoints or measured components **and cannot be bound to an assignment different from their immutable coordinate stream's assignment**, including same-source destinations A and B.
I-12: raw and metric records are non-destructively versioned and the source selection choice is reconstructible.
Map I-01..I-12 to AT-007..AT-019, AT-023 in [09 acceptance](09_VALIDATION_AND_ACCEPTANCE.md).

## 11. Corrective cardinalities, constraints and projection semantics (CR-1)
**CR-2 identity qualification:** A provider's rolling request windows and volatile response generation duration never mint a new stream or a new semantic model snapshot. The app preserves both byte-level raw digest and versioned semantic digest, with `issued_at=null` for unverified Best Match run identity. Full outer envelope HMAC replay nonce is independent of first-seen sensor event idempotency; see [03 §10](03_TARGET_ARCHITECTURE.md) and the my-pa constraint contract [04 §7](04_POSTGRESQL_INTEGRATION.md).

**Binding implementation contract:** [04 §7](04_POSTGRESQL_INTEGRATION.md); no DDL or runtime is authorized by this planning change.

1. **Identity hierarchy.** `location_id` identifies a display destination, `source_id` an authorized station/provider origin, `assignment_id` a half-open origin→destination period, `device_id` an evidenced physical sensor epoch, `event_id` immutable received/provider-retrieval metadata, and `stream_id` one immutable polling product (not a rolling absolute request window). A shared measured NWS station stream may serve two active destinations only if the true site/product matches; coordinate-model/forecast stream is bound to a specific assignment and versioned relative horizon, with an independent cursor. Changed product/geography creates a new operator-approved stream.
2. **Enforcement.** Composite source/event/assignment keys plus physical `(event_id,source_id,device_id)` FK require equality with parent `raw_events.device_id` for a DB-derived local RF source; remote NULL-device semantics require a separate null-safe guard, as ordinary PostgreSQL nullable composite FK alone bypasses checking. Two actual devices sharing `station_id` cannot exchange observation provenance. Source-row/physical epoch/assignment locking prevents concurrent overlapping intervals and invalid retired-device writes. Model retrieval `model_runs(event_id,source_id,stream_id)` must FK by RESTRICT to original `raw_events` with matching provider stream/source, and model values must match run/assignment. No branching correction chains or mutable accepted history. Only audited operator `weather_admin_cli` controls registration. SC-01..SC-05 must exercise success and adversarial cross-links with valid UUID test aliases.
3. **Proof across payload retention.** Event metadata/digest/source/device/stream remain as long as any observation or model run references them. Optional `raw_event_payloads` bytes may expire only under later exact operator policy; a synthetic 90-day payload/24-month observation example proves future FK compatibility, not deletion authority. Model value→run→raw event/digest must remain queryable after bytes expire. No claim of byte-identical re-normalization after expiry.
4. **Derived rain on read.** Only `rain_counter` itself is `MEASURED`. `/api/v1/locations/{location_id}/derived` and `/summary` compute interval increments/rate/day totals from effective accepted consecutive samples of the same source/device epoch, with prior/current observation UUID, UTC interval, selected source policy, query `as_of_ingested_at`, algorithm version, reset/rollover/gap/local midnight/DST completeness and a `DERIVED` type. Any missing prior, possible rollover, unprovable midnight crossing, long gap or out-of-order invalid correction yields `value: null`/quality or an explicitly partial daily total, **never a fabricated zero**. Corrections append observed predecessor chain and trigger deterministic recomputation for matching as-of cutoff; no derived observation is stored as physical measurement.
5. **Decoder truth.** Both pinned [`fineoffset.c` @ 3792adf](https://github.com/merbanan/rtl_433/blob/3792adf1075acb7c6447f7c27df9920fd4f2d41a/src/devices/fineoffset.c#L307-L445) and newer [@ 406f9a3](https://github.com/merbanan/rtl_433/blob/406f9a33550a2b6b3d0d8a8a486417ce5b3f13ab/src/devices/fineoffset.c#L307-L445) populate optional pressure in `type == MODEL_WS69`, **not `MODEL_WH65`**; distinct [WH32B decoder](https://github.com/merbanan/rtl_433/blob/3792adf1075acb7c6447f7c27df9920fd4f2d41a/src/devices/fineoffset.c#L639-L688) can emit pressure when correct actual model/payload checks pass. Actual installed hardware and pressure remain `UNRESOLVED` until Gate-RF.

**Crosswalk:** `LHW-RV-001/002/003/004/005/007` → `D-001/004/005/007/008/009` → `WP-004/005/006/007/008` → `AT-004/007/008/011/012/013/014/016/018/019/021/023`, and invariants I-01–I-12. Future scratch tests, not this planning commit, prove enforcement.

## 12. CR-3 NF-001 geographic owner rule — no data-class loophole

CR-2 reviewer `LHW-CR2-NF-001` (`PLAN_REVISION_REQUIRED` at old HEAD `d0739f9e4ceba5ee45e8ba8ab8891cb68c994e23`) identified two separately valid source-level FKs that still allow same-source destination A's model stream to be labeled as destination B. The decisive [04 §8](04_POSTGRESQL_INTEGRATION.md) contract replaces that ambiguity with **two mandatory composite stream+source+assignment+class foreign keys** on modeled values and an equally qualified run-parent FK, with all modeled parent/child components non-null. A future forecast `valid_from` outside an assignment's active epoch does **not** retarget the underlying run; its registered origin assignment was resolved at true issue or retrieval time and is immutable. `FORECAST_MODEL` and `MEASURED_STATION` are DB-owned disjoint classes, not provider JSON hints.

**Future isolated proof:** Given common S, valid assignment a→A and b→B, rA/sA/a succeeds and rB/sB/b succeeds, while value `rA/sA/S/b` is rejected even though b/S is valid. A model run itself cannot be filed against b while referencing stream sA/a. The physical NWS measured-station stream has a NULL owner and can yield correctly separate **MEASURED_REMOTE** observations for a and b; its NULL must never weaken modeled FK checks. Concurrent retirement versus retrieval records the original epoch; no historical repointing. Map to SC-02/05, I-01/06/11/12, AT-011/013/016/021, WP-004/005/007. All tests are `NOT_RUN`; actual my-pa DDL needs a separate operator authorization.
