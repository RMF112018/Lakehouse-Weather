# Local RF operations

The reviewed receiver uses cached immutable image `sha256:d46c11edfc6029a1f7d603ccf0cb7fb1c6bdee848b5a9a03e6bb9323eedfc6e6`, bound to `hertzg/rtl_433@sha256:79243e8ebc0ee086603d34789aca905be50b99e328cef72f927f1a47c0233a0e`. This is image-scoped decoder provenance, not cryptographic authentication of a radio transmitter. The pinned receiver image identifies an executable artifact; it does not prove binary-to-upstream-source-commit binding. Actual current packet semantics have been validated for WH65B only; the configured WH32B source remains unverified until its own packet arrives. Exact model, approved sensor ID, protocol 78, CRC and configured source profile gate admission. Nearby radio packets never enter the journal, database or logs.

The root launcher freshly resolves USB vendor/product `0bda:2838` at topology `1-2`, checks its current bus/device character node, and passes only that node into the receiver. It uses 915MHz, decoder78, classic mode, 250ksps and UTC/protocol JSON. The receiver has no network, Docker logs, writable root filesystem, broad device mount or added capability. Its stdout goes directly into `docker exec -i ... python -m weather collect`; the collector uses the already mounted database credential without exposing its contents. No ingestion HTTP route, new network or token is involved.

The collector resolves its allowlist before normalization or persistence. Each normalized event is written to a private journal file and fsynced, followed by directory fsync, before any database insert. Only a committed insert or exact duplicate permits deletion and directory fsync. Ambiguous commit failure replays the same event; a differing event at the same source/time retains the file and halts capture. The journal defaults to 256MiB and 50,000 events, with a 64KiB per-event bound. Pending age over seven days stops replay for operator reconciliation; there is no age deletion. Database failure retries every five seconds and stops reading further RF data, applying pipe backpressure. Finite pipe buffers are not durable RF evidence: radio reception during outages can be lost before admission.

The journal must preexist at `/volume1/weather-dashboard/rf-journal`, UID/GID10001 and mode0700. It mounts only into the dashboard at `/var/lib/weather-rf`. A process lock excludes concurrent collectors. On startup, replay completes before new input is consumed. Incomplete files, capacity exhaustion and malformed journals fail closed; retain them for bounded private reconciliation, never clear the directory as recovery. `status.json` contains bounded counters, receipt/commit/update timestamps, pending count/bytes/age and a fixed error code. It contains no payloads, sensor IDs, coordinates or credentials. Counters survive restart. Status may be stale when no RF is received; freshness of measurements remains source-specific.

## Reviewed NAS activation sequence

These are proposed actions for the authorized root operator. Substitute only action-time reviewed hashes and non-secret container/image identities; keep approved sensor IDs in the private operator invocation rather than source, receipts or chat output.

1. Verify the exact reviewed source head/tree, independently reviewed dashboard image and its OCI provenance. Transfer reviewed source as root-owned files beneath the root-owned `/volume1/weather-dashboard/<head>/` directory. Do not install dependencies or pull images.
2. Create only the private RF journal directory, mode0700 owner10001:10001. Read the existing registry's SHA256 as bounded metadata. Run `ops/nas/commission_rf.py` with the exact expected hash, private approved `--wh65-id` and `--wh32-id`, and action-time `--dashboard-id`/`--dashboard-image`. Run its preflight first, then `--apply`. The helper preserves all non-RF fields including coordinates, permits a first binding only from the exact disabled `PENDING_RF_COMMISSIONING` marker (or an unchanged identity) and refuses replacement of prior real identities, retains a root0700 NAS-only backup, atomically updates the registry, and emits hashes only. It does not touch credentials or connect to a database. The dashboard image performs full registry validation at startup.
3. Run the existing reviewed dashboard-only updater with exact previous dashboard/image identity and new head/tree/image. Its Compose invocation receives `WEATHER_RF_JOURNAL_PATH`; it recreates only the dashboard. Verify dashboard health and unchanged forecast/database identity. Registry synchronization occurs in the dashboard's existing startup path; no owner-schema migration is introduced.
4. Compute the reviewed launcher's SHA256. Run `/usr/bin/python3 -I -B <reviewed>/ops/nas/rf_capture.py --dashboard-id <id> --dashboard-image <image> --source-sha256 <sha256> --reviewed-head <head> --reviewed-tree <tree>` for action-time preflight. Actual capture adds `--apply` and runs in the foreground. Root-owned source custody, source hash, dashboard image labels/health, cached receiver image, current USB and private journal mount are rechecked.
5. For continuous recovery, invoke the same command with both `--apply --install-supervisor`. It exclusively creates `/etc/cron.d/weather-rf-capture`, root0600, with a once-per-minute exact `/usr/bin/python3 -I -B` invocation and discarded stdout/stderr. Existing entries are never overwritten. The host lock means ticks cannot create concurrent receivers. A stale receiver is removed only when its exact name, image, weather ownership labels, network-none and logging-none contracts match; ambiguity halts for review. After a crash, queued events replay before new input. A conflict/age/capacity status blocks receiver restart until reconciliation.
6. Observe a real scheduler tick in root-only `/volume1/weather-dashboard/rf-runtime-status.json`, advancing across ticks while the launcher holds its lock; verify accepted observations in the protected dashboard and sanitized database aggregates. A written cron file alone does not prove recovery. A reboot has not been exercised by this source change.

Stop only the owned launcher/receiver and remove only this exact reviewed scheduler entry when explicitly retiring RF. Preserve pending journal events and private registry backups. Deliberate dashboard replacement requires rebinding the supervisor to the new reviewed identity; it must not silently follow a mutable name.

WH65B reception and a fresh WH32B reception are separate evidence. A configured WH32B allowlist does not prove it has recently transmitted. The UI must show its source as missing until its own committed observation arrives, without substituting WH65B temperature/pressure.
